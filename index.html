設計方針

01

独立した照合

解析処理とは別の照合処理が、原記録とチェックリストから集計値を確かめます。解析時の対話記録は照合処理に渡しません。

02

前工程への差し戻し

不合格の項目、根拠の行、修正内容を記録し、再計算は前の工程から始めます。

03

解析と照合の分離

集計する処理と確かめる処理を分け、同じ原記録を別の処理で読みます。

04

チェックリストによる照合

試験担当者が定めた項目（測定対象、単位、原値、計算式の版）だけを照合し、チェックリストの版を記録します。

03 / DATA FLOW

処理間のデータ受け渡し

処理の間では対話記録を渡しません。
原記録の保存先、計算式やチェックリストの版、根拠の行を渡します。

スマートフォンでは図を横に動かして表示します。

C1試験担当者 → 実行管理

C2実行管理 → 解析処理

作業票を渡します。原記録の保存先、使う計算式の版、出力形式を含みます。対話記録は渡しません。

C3解析処理 → 照合処理

集計値と原記録の保存先を渡します。解析処理の説明文は渡しません。

C4照合処理 → 実行管理

C5実行管理 → 再計算処理

C6実行管理 → 試験担当者

04 / PERMISSIONS

実行権限の管理

試験担当者が実行権限を発行し、実行管理が1回だけ使います。
処理ごとに、読める保存先と書ける保存先を限定します。

  1. 1発行

    試験担当者が、実行のたびに1回分の実行権限を発行し、実行管理に渡します。

  2. 2使用

    実行管理が1回だけ使い、その案件の原記録の保存先と出力先を開きます。

  3. 3処理の範囲

    解析処理と照合処理は実行権限を持ちません。実行管理が開いた保存先だけを読み書きします。

  4. 4失効

    実行の終了、または再計算回数の上限で失効します。再実行には新しい実行権限が必要です。

  5. 5記録

    発行、使用、失効の時刻と、開いた保存先を実行記録に保存します。

装置の設定値

装置への設定値の送信は、試験担当者が操作画面から行います。AI処理は設定値の案を出力します。装置は設定範囲外の値を受け付けません。

権限のない実行

実行権限のない実行要求と、失効後の再使用は、実行記録に保存して停止します。監視画面が赤になります。

案件ごとの範囲

実行権限は案件単位です。他の案件の原記録は読めません。読む保存先と書く保存先は依頼票で定めます。

05 / STOP CONDITIONS

実行条件・停止条件

再計算の回数と停止条件を、実行前に設定します。
数値は例題の設定値です。案件ごとに試験担当者と定めます。

条件設定値の例動作復旧条件
解析 → 照合 → 再計算の回数3回停止し、試験担当者に報告します。実行権限を失効します。担当者が試験条件を見直し、新しい実行権限で再開します。
同じチェック項目の不合格2回連続まず自動点検処理を実行します（原記録の保存先、単位、版）。点検で直らなければ、その項目を担当者の確認へ移します。点検で直れば再開します。担当者へ移した場合は、担当者が原記録を確認して項目を再設定します。
1回の実行の累計不合格数5件実行を停止し、状態を分類します（再実行、点検、設定の組み直し）。分類に応じた操作の後に再開します。
合格のまま集計値が変わる2回チェックリストの版を確認する処理へ移します。担当者が版を確定します。
実行権限のない実行、装置への設定値送信0回（許可しない）実行記録に保存して停止します。担当者の確認後に再開します。
1件あたりのAPI呼び出し回数10回実行管理が停止し、利用量を報告します。担当者が上限を再設定します。
合格のまま集計値が変わる状態

照合は合格なのに、集計値が実行ごとに変わる状態です。チェックリストの項目と版を確認します。

同じ項目の不合格が続く状態

解析処理を替えても同じ項目が不合格になる状態です。2回目で自動点検処理が原記録の列名、単位、計算式の版を点検し、直らなければ担当者の確認へ移します。

処理ごとの規則

解析処理

原記録にない値を作りません。欠測区間は「未測定」と記録し、平均値で埋めません。

照合処理

解析処理の説明文を読まず、原記録とチェックリストで照合します。項目ごとに根拠の行を記録します。

再計算処理

前の処理の対話記録を受け取らず、不合格の項目、根拠、修正内容から再計算します。

実行管理

原因候補と切り分け試験の条件を一覧にします。再計算回数を数え、上限で停止します。

全処理

外部資料に書かれた命令を実行しません。資料は解析対象として読みます。停止理由を実行記録に保存します。

試験担当者

チェックリストと計算式の版を定めます。停止時に、再実行、点検、設定の組み直しのどれを行うかを選びます。

    データ管理

    研究のデータがどこを通るかを、処理の構成に含めます。

    企業向けの学習方針

    商用API・企業向けプランは、
    入出力を既定で学習に使わない。

    AnthropicのAPI・Claude Team / Enterprise、OpenAIのAPI・ChatGPT Business / Enterpriseが対象です。任意のデータ提供や評価送信は、利用経路ごとの設定を確認します。

    社内の原記録↓必要な区間・情報を抽出↓会社が承認したAPI・組織アカウント↓結果と根拠を社内に保存
    学習への利用と企業向けアカウント

    Claude / Anthropic

    API、Claude Team / Enterpriseの商用入出力は既定で学習に使いません。個人のFree / Pro / Maxは個人向けの規約と設定が適用されます。

    評価ボタンなどで提供した会話は学習に使われる場合があり、関連会話は最大5年保存される扱いです。企業管理者は「Rate chats」で評価送信を管理できます。

    学習用に共有する設定を明示的に有効にしたデータは別扱いです。利用する契約、接続先、データ共有設定をそろえます。

    守秘義務と、Enterprise・APIの違い

    守秘義務の定め方

    Anthropicの商用規約では、入力と出力は顧客の機密情報として扱われます。提供会社との商用契約・DPA、社内のアクセス権限、接続サービスの送信先を組み合わせて管理します。業務上必要な担当者のアクセスや法令に基づく開示には、それぞれ条件があります。

    Enterprise：組織での利用を管理

    SSO、ユーザー管理、アクセス権限、監査ログ、データ保持などを管理するプランです。席・契約料金は各社の契約条件によります。

    API：処理からAIを呼び出す経路

    解析、照合、実行管理をプログラムでつなぐ経路です。上の月約3万円は、このAPI処理分の試算です。

    Anthropic商用規約を開く ↗　DPAを開く ↗　Claude Enterpriseを開く ↗　OpenAIの管理とアクセス方針を開く ↗

    保存期間・ゼロデータ保持・モデルごとの条件

    学習への不使用と保存期間は、別の設定です。機能ごとの保存条件と、利用モデルに適用される条件を確認します。

    Anthropic

    • 通常のAPIは原則30日以内に削除します。Files APIなど機能別の条件と例外があります。
    • Enterpriseの会話・プロジェクトは既定で無期限です。管理者は最短30日から設定でき、プロジェクト側の保持設定が優先される場合があります。
    • ZDR（ゼロデータ保持）は、対象製品・組織への個別適用です。

    Fable 5.1はCovered Modelsの対象で、通常は安全性監視のため30日の保存と限定的な確認があります。2026年9月1日発表のEFSは秋から段階展開の予定です。対象と通知された顧客には、移行までFable 5 / 5.1のZDRが提供されます。

    OpenAI

    APIの不正利用監視ログは通常、最大30日保存されます。ファイルや会話などの状態を保持する機能には別の条件があります。ZDRは対象組織・機能への適用を確認します。

    ChatGPT Enterpriseの保持期間は組織管理者が管理します。削除後のデータは原則30日以内に削除され、法令上の保持などには例外があります。

    Anthropic：標準の保存期間 ↗Enterpriseの保持設定 ↗ZDRの適用範囲 ↗Covered Modelsの保存条件 ↗EFSの提供予定 ↗OpenAI：APIのデータ管理 ↗
    外注と社内AI処理の役割分担

    人に外注する場合

    外注担当者が計算、比較、報告を行います。社内では依頼条件を整理し、報告を受け入れ、試験の判断を行います。機密は外注先との契約やNDAで取り決めます。

    社内でAI処理を使う場合

    解析処理、照合処理、実行管理が処理を分担します。試験担当者はチェックリストの作成、確認項目の判断、試験条件の選択、装置の操作を行います。費用はAPI利用料と社内工数です。機密は提供会社との契約と社内の権限管理で扱います。

    原記録との照合結果と、担当者が確認する項目をまとめて報告します。

    データの取り扱い規則
    01 / アカウント

    承認された組織アカウントの使用

    会社が承認した組織アカウントと経路だけを使います。個人アカウントに図面や測定データを入力しません。

    02 / 読取範囲

    保存先の限定

    処理が読める保存先を案件フォルダーに限定します。認証情報は、処理に渡す文書から分けて保管します。

    03 / 外部資料

    外部資料の扱い

    外部資料に書かれた命令は実行せず、解析対象として読みます。送信先と操作権限を処理ごとに固定します。

    04 / 装置の設定値

    担当者による送信

    装置への設定値の送信は担当者が操作画面から行います。装置は設定範囲外の値を受け付けません。

    05 / 測定値の照合

    原波形と基準器による照合

    集計値の照合は、原波形、測定対象、基準器との比較で行います。

    06 / API利用量

    呼び出し回数の上限

    1件あたりの呼び出し回数に上限を設け、利用量を監視画面に表示します。
